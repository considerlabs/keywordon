## 1. 서비스 개요 및 아키텍처

### 1.1. 시스템 목적
* **자체 마케팅 및 크리에이터 도구 내재화**: 네이버 블로그 최적화, 황금 키워드 발굴, 실시간 순위 모니터링 및 AI 초안 작성을 외부 상용 서비스 결제 없이 무료로 자동화합니다.
* **무비용 운영 모델**: 
  * 데이터 수집: **네이버 검색광고 API (무상 발급)** [91] 및 **BeautifulSoup/Selenium 크롤러** 활용.
  * 프론트엔드/백엔드: HTML/CSS/JS 프레임워크 학습 비용이 없는 파이썬 **Dash(Plotly)** 기반 단일 아키텍처 [23].
  * 데이터베이스: 경량 로컬 파일 DB인 **SQLite3**를 사용하여 별도의 호스팅 비용 차단.

### 1.2. 기술 스택 (Tech Stack)
* **Frontend/Backend**: Python 3.12, Dash (v2.7.0+) [25], Plotly (v5.11.0+) [25]
* **Database**: SQLite3 (Python 내장 라이브러리)
* **Data Scraper**: BeautifulSoup4, Selenium WebDriver, Requests
* **AI/LLM Integration**: OpenAI API / Gemini API (GPT-4o 또는 Gemini 1.5 Flash API Key 연동 - 호출량 제어용 로컬 캐싱 구현)

## 4. API 연동 및 웹 데이터 크롤링 설계

### 4.1. 네이버 검색광고 API 연동 가이드

네이버 검색광고 API는 기존의 일반 OAuth 2.0과 달리 **매 요청마다 생성해야 하는 HMAC-SHA256 암호화 서명**을 요구합니다. [90] 또한, 광고비 지표가 원화 정수로 제공되며, ROAS 필드가 % 단위(예: 350%를 350으로 반환)로 수집되기 때문에 전처리가 필수적입니다. [97, 98]

#### 4.1.1. HMAC-SHA256 인증 서명 헤더 생성 로직
```python
import hmac
import hashlib
import base64
import time
import requests
import json

def get_naver_ad_headers(method: str, uri: str, api_key: str, secret_key: str, customer_id: str):
    """
    네이버 검색광고 API 전용 HMAC-SHA256 인증 헤더를 생성합니다.
    """
    # 1. 밀리초 단위 타임스탬프 계산 [92, 93]
    timestamp = str(round(time.time() * 1000))
    
    # 2. 메시지 서명 가공 규칙 [93]
    message = f"{timestamp}.{method}.{uri}"
    
    # 3. Secret Key를 활용하여 HMAC-SHA256 해시 암호화 수행 [93]
    hashed_raw = hmac.new(
        secret_key.encode('utf-8'),
        message.encode('utf-8'),
        hashlib.sha256
    ).digest()
    
    # 4. Base64 인코딩 후 디코딩 [93]
    signature = base64.b64encode(hashed_raw).decode('utf-8')
    
    # 5. 필수 4개 헤더 매핑 [92, 93]
    return {
        "X-API-KEY": api_key,
        "X-CUSTOMER": customer_id,
        "X-Timestamp": timestamp,
        "X-Signature": signature,
        "Content-Type": "application/json; charset=UTF-8"
    }
```

#### 4.1.2. API 키 사용 및 92일 호출 한계 극복 기획 [103]
네이버 광고 API의 `/stats` 엔드포인트는 한 번에 조회할 수 있는 최대 조회 기간이 **92일**로 한정되어 있습니다. [103] 최근 1년간의 키워드 통계를 시계열로 분석하기 위해서는 조회하려는 기간을 **90일 단위로 쪼개어 분할 호출한 뒤 데이터를 병합(Merge)**하는 슬라이딩 윈도우(Sliding Window) 알고리즘을 적용하여 설계합니다.

```python
from datetime import datetime, timedelta

def split_date_ranges(start_date: datetime, end_date: datetime, max_interval_days: int = 90):
    """
    92일 제한을 우회하기 위해 날짜 범위를 max_interval_days 단위로 쪼갭니다.
    """
    ranges = []
    current_start = start_date
    while current_start < end_date:
        current_end = current_start + timedelta(days=max_interval_days)
        if current_end > end_date:
            current_end = end_date
        ranges.append((current_start.strftime("%Y-%m-%d"), current_end.strftime("%Y-%m-%d")))
        current_start = current_end + timedelta(days=1)
    return ranges
```

### 4.2. BeautifulSoup & Selenium 기반 스마트스토어 상품 검색 순위 추적 크롤러 [18]

스마트스토어에 등록된 내 상품이 네이버 쇼핑 검색 결과에서 광고 상품을 배제하고 **실제 몇 번째에 노출되고 있는지**를 실시간으로 추적하는 파이썬 크롤링 아키텍처입니다. [17]

* **작동 원리**: URL을 직접 변형하여 페이지를 빠르게 이동하고, 페이지 바닥까지 스크롤을 내려 반응형 데이터를 완전 렌더링한 후, `data-i` 혹은 고유 상품 코드 속성을 타겟팅하여 인덱스 번호를 계산합니다. [14, 15, 18]

```python
import time
from bs4 import BeautifulSoup
from selenium import webdriver
from selenium.webdriver.chrome.options import Options

def track_product_ranking(target_product_id: str, search_keyword: str, max_pages: int = 5):
    """
    BeautifulSoup과 Headless Chrome Selenium을 활용하여 특정 키워드 검색 시 내 상품의 쇼핑 노출 순위를 추적합니다.
    """
    chrome_options = Options()
    chrome_options.add_argument("--headless")  # 화면 없이 백그라운드 구동 [ headless ]
    chrome_options.add_argument("--no-sandbox")
    chrome_options.add_argument("--disable-dev-shm-usage")
    
    driver = webdriver.Chrome(options=chrome_options)
    
    true_rank = -1
    found_page = -1
    
    try:
        for page_idx in range(1, max_pages + 1):
            # URL 단위 쿼리로 직접 접근하여 탐색 속도 향상 [18]
            url = f"https://search.shopping.naver.com/search/all?query={search_keyword}&pagingIndex={page_idx}&pagingSize=40"
            driver.get(url)
            time.sleep(2)  # 네트워크 로딩 대기
            
            # 페이지를 바텀까지 5회에 걸쳐 고속으로 내려서 숨겨진 상품 노출 유도 [14, 15]
            for scroll_step in range(5):
                driver.execute_script("window.scrollBy(0, 1500);")
                time.sleep(0.4)
            
            # BeautifulSoup 파싱 객체 변환
            html = driver.page_source
            soup = BeautifulSoup(html, 'html.parser')
            
            # 네이버 쇼핑 상품 카드 리스트 타겟팅
            # 각 상품별 고유 식별자 data-i 속성을 기준으로 탐색 [14]
            product_elements = soup.find_all('a', attrs={'data-i': True})
            
            local_rank = -1
            for idx, element in enumerate(product_elements):
                # 타겟팅 상품 아이디와 일치하는 엘리먼트 검색
                if str(element.get('data-i')) == str(target_product_id):
                    # 광고 엘리먼트 제거 및 순수 상품 노출 인덱스 추출 [17]
                    local_rank = idx + 1
                    break
            
            if local_rank != -1:
                # 네이버 쇼핑의 1개 페이지당 40개 고정 출력 기준 진짜 통합 등수 계산 공식 적용 [15, 16]
                true_rank = (page_idx - 1) * 40 + local_rank [15, 16]
                found_page = page_idx
                break
                
            time.sleep(1)
            
    except Exception as e:
        print(f"크롤링 분석 중 예외 발생: {str(e)}")
    finally:
        driver.quit()
        
    return {"ranking": true_rank, "page": found_page}
```

## 5. 통합 데이터베이스(DB) 및 데이터 모델 설계

개인 개발 목적에 맞게 복잡한 인프라 관리 비용이 들지 않는 단일 파일 관계형 데이터베이스 **SQLite3** 스키마를 제안합니다. 네이버 API 데이터의 주요 특징인 **마스터 정보(Ncc Campaign)와 통계 정보(Stats)의 엄격한 분리 구조**를 극빙하기 위한 전용 데이터 구조로 설계되었습니다. [94, 95]


### 5.1. DDL SQL 스키마 명세
```sql
-- 1. 네이버 캠페인 마스터 테이블 (이름 정보 캐싱 보관용) [95, 100]
CREATE TABLE IF NOT EXISTS naver_campaign_master (
    ncc_campaign_id TEXT PRIMARY KEY,
    campaign_name TEXT NOT NULL,
    campaign_type TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 2. 일별 통계 성과 데이터 테이블 [95, 96, 100]
CREATE TABLE IF NOT EXISTS naver_daily_stats (
    stat_id INTEGER PRIMARY KEY AUTOINCREMENT,
    ncc_campaign_id TEXT NOT NULL,
    target_date DATE NOT NULL,
    imp_cnt INTEGER DEFAULT 0,          -- 노출수 [96]
    clk_cnt INTEGER DEFAULT 0,          -- 클릭수 [96]
    sales_amt INTEGER DEFAULT 0,        -- 광고비 (원화 정수) [96]
    avg_rnk REAL DEFAULT 0.0,           -- 평균노출순위 (네이버 고유지표) [96]
    conversions INTEGER DEFAULT 0,      -- 전환수 [96]
    conv_amt INTEGER DEFAULT 0,         -- 전환매출액 [96]
    roas_multiplier REAL DEFAULT 0.0,   -- ror % 단위를 100으로 나눈 표준 배수값 [98, 100]
    FOREIGN KEY(ncc_campaign_id) REFERENCES naver_campaign_master(ncc_campaign_id),
    UNIQUE(ncc_campaign_id, target_date) -- 중복 가입 방지 인덱스
);
```

### 5.2. 일별 성과 통합 조인(JOIN) 분석 쿼리
네이버 성과 API 결과물(`/stats`)은 캠페인 ID만 제공되므로 명칭을 매핑하고, 타 매체와 단위를 표준화하여 하나의 분석 테이블로 묶어냅니다. [95, 98]

```sql
SELECT 
    s.target_date AS "날짜",
    m.campaign_name AS "캠페인명",
    s.imp_cnt AS "노출수",
    s.clk_cnt AS "클릭수",
    s.sales_amt AS "광고비(원)",
    ROUND(CAST(s.clk_cnt AS REAL) / NULLIF(s.imp_cnt, 0) * 100, 2) AS "클릭률(%)",
    s.avg_rnk AS "평균노출순위",
    s.conversions AS "전환수",
    s.conv_amt AS "전환매출",
    -- ror % 단위를 타 매체(구글, 메타) 통일 기준인 소수점 배수로 변환하여 산출 [98, 100]
    s.roas_multiplier AS "ROAS(배수)"
FROM naver_daily_stats s
INNER JOIN naver_campaign_master m ON s.ncc_campaign_id = m.ncc_campaign_id
ORDER BY s.target_date DESC, s.sales_amt DESC;
```
