## 1. 핵심 인사이트 (3문장)

1. 판다랭크는 더 이상 "키워드 분석 툴"이 아니라 **글감 추천 → AI 초안 → 발행 → 진단 → 숏폼 → 수익화(쇼핑커넥트/애드포스트/체험단)** 를 잇는 **크리에이터 워크플로 OS**로 전환을 끝냈습니다. (근거: `/ai-flow` 홈이 "오늘의 글감 7 / AI 초안 생성 0 / 포스팅 발행 0"의 **파이프라인 카운터** 구조)
2. 수익 모델의 축은 요금제가 아니라 **3중 게이팅**입니다: ①크레딧(AI 생성) ②횟수 제한(진단 주 1회, 인플루언서 검색 일 3회) ③**Chrome 확장 설치 강제**(경쟁자 블로그·최근 게시글 진단·브랜드커넥트 글감). 확장 설치는 과금이 아니라 **데이터 수집 채널**로 보는 것이 타당합니다.
3. KeywordOn의 현재 자산(`/`, `/bulk`, `/discover`, `/copilot`)은 판다랭크의 **입력부만** 커버합니다. 격차의 본질은 기능 개수가 아니라 **"내 자산(블로그·글) 축"과 "시계열 스냅샷 DB"의 부재**이며, 이 둘이 없으면 진단·순위추적·페르소나 AI가 전부 구현 불가입니다.

## 3. 화면별 상세 스펙 (캡처 원문 우선)

### 3.1 키워드 분석 홈 — `/content/detail`

캡처에 실제로 있는 요소:

- 헤드라인: **"오늘 콘텐츠, 어떤 키워드로 시작할까요?"**
- 검색 인풋 + `[🔍 분석]` + `[✨ 급상승 키워드]`
- 프로모 카드 2종
  - "콘텐츠 키워드 고민된다면? **블로그 작성 시간 5배 단축하는 치트키**"
  - "왜 내 글은 검색 노출이 안되지? **노출되는 판다 AI 블로그 글쓰기**"
- **인기 검색어** 섹션, 우측 상단에 `2026.08.21 15:48 기준` 타임스탬프
  - 좌측: `실시간🔴` / `더보기 ›` — 예: 김욱숙 자택 압수수색, 손승원 음주운전 징역 2년, 미래대응기금 산업, 청년 최고 전용기 인격 ⚠️판독 불확실
  - 우측: `네이버 / 구글 / 판다랭크` 3소스 토글 — 예: gv90 가격, 다이소 품절 대란·안 사서 후회하는 아이템, 올린기, 제네시스 gv90 ⚠️판독 불확실
  - 모든 행 우측에 `AI 자동화 ›` 버튼

설계 관점 해석: 검색어 리스트의 각 행에 **"AI 자동화"** 버튼을 붙인 것이 핵심입니다. 조회(read-only)를 즉시 생성(action)으로 연결해 **이탈 지점을 제거**하는 구조이며, 이 CTA는 캡처 4개 화면(`/content/detail`, `/golden-keyword`, `/golden-keyword/trend`, `/ai-flow`)에 반복 등장합니다.

### 3.3 실시간 급상승 — `/golden-keyword/trend`

### 3.5 블로그 진단 — `/content/diagnosis`

- 입력: "네이버 블로그 URL을 입력해 주세요" + `[🔍 분석]`, 우측 `이번 주 1회 분석 가능` `[추가 분석하기]`
- 결과 헤더: **"기로킴의 머니 아카이브의 랭킹은 전체 2,901위예요"** / "최근 5일 방문자 수 18,258명, 현재 채널 영향력은 A등급이에요!" / `[오늘 기준으로 다시 진단]`
- 시각화 3종 병렬 배치

### 7.2 대시보드 컴포넌트 (판다랭크 `/ai-flow` 벤치마킹 + 개선)

| 영역 | 컴포넌트 | 판다랭크 대비 개선점 |
|---|---|---|
| 상단 | 채널 카드 + 등급 + 최근 5일 방문자 | 동등 |
| 좌열 | 오늘의 글감 N개 (출처 배지 + 월 검색량) | **다계정 지원** — 블로그별 탭 |

### 7.3 절약 가치 산식 (P0, 구현 난이도 최하)

```typescript
// lib/savings.ts
// 왜: 사용량(횟수)은 지불 정당화가 안 되지만, 시간·비용 환산은 갱신률에 직접 기여한다.
//     판다랭크 마이페이지의 "이번 달 이만큼 아꼈어요" 패턴을 산식 공개 방식으로 개선.

/** 작업별 수동 소요 시간(분). 근거 없는 값은 쓰지 않는다 — 사내 측정치로 교체 필요. */
const MANUAL_MINUTES: Record<string, number> = {
  keyword_lookup: 3,    // 검색량 수동 확인 1건
  bulk_lookup: 90,      // 50개 수동 조회 (3분 × 50 × 0.6 숙련보정)
  draft: 30,            // 판다랭크 공개 카피 "포스팅 30분 단축" 인용
  post_diagnose: 20,    // 상위 10개 문서 수동 비교
};

export interface SavingsInput {
  counts: Record<string, number>;
  hourlyWageKrw?: number; // 기본값: 2026년 최저임금 아님 — 사용자 설정값 우선
}

export interface SavingsResult {
  minutes: number;
  hours: number;
  krw: number;
  breakdown: Array<{ action: string; count: number; minutes: number }>;
}

export function computeSavings({
  counts,
  hourlyWageKrw = 20000, // 확인 필요: 프리랜서 블로거 평균 단가로 재설정 권장
}: SavingsInput): SavingsResult {
  const breakdown = Object.entries(counts).map(([action, count]) => {
    const unit = MANUAL_MINUTES[action] ?? 0;
    if (unit === 0) {
      // 미정의 액션은 0으로 처리하되 로깅 — 조용한 누락은 신뢰를 깎는다
      console.warn(`[savings] unknown action: ${action}`);
    }
    return { action, count, minutes: unit * count };
  });

  const minutes = breakdown.reduce((sum, b) => sum + b.minutes, 0);
  return {
    minutes,
    hours: Math.round((minutes / 60) * 10) / 10,
    krw: Math.round((minutes / 60) * hourlyWageKrw),
    breakdown, // UI에서 "어떻게 계산했나요?" 토글로 전부 공개
  };
}
```

실행: `npx tsx lib/savings.ts` 또는 대시보드 서버 컴포넌트에서 직접 호출.
주의: `MANUAL_MINUTES`는 **가정값**입니다. 실측 없이 마케팅 수치로 쓰면 과장 광고 리스크가 있으므로, UI에 산식을 노출하고 사용자가 시급을 직접 입력하게 하십시오.

### 7.4 페르소나 학습 파이프라인 (P0)

```
POST /api/persona/analyze  { blogUrl }
  ├ 1) 최근 30개 글 수집 (Naver Open API blog.search + RSS)
  ├ 2) 카테고리 분포 집계        → step:"category"   (SSE push)
  ├ 3) 평균 글자수·문장길이·어미 → step:"tone"
  ├ 4) 상위 5개 글 구조 패턴     → step:"pattern"
  ├ 5) 댓글·공감 반응 집계       → step:"reaction"
  └ 6) LLM 요약 → persona JSON  → step:"report"
GET  /api/persona            현재 페르소나 조회
PATCH /api/persona           사용자 수정 반영 (핵심: 편집 가능해야 "내 AI"가 됨)
```

산출 스키마:

```json
{
  "oneLiner": "직접 다녀온 경험으로 여행의 시행착오를 줄여주는 실전형 채널",
  "tone": { "ending": "해요체", "avgChars": 2400, "avgSentence": 42 },
  "structure": ["훅 2문장", "목차", "본문 3~5섹션", "요약 박스", "CTA"],
  "audience": "30~40대 자유여행 준비 단계",
  "avoid": ["과장된 감탄사", "협찬 티 나는 표현"],
  "editedByUser": false

```

이 JSON을 `/copilot/draft`의 시스템 프롬프트에 주입하면, 코퍼스 없이도 판다랭크의 "내 스타일 참고 🔒" 기능과 동등한 체감을 만들 수 있습니다. **투자 대비 효과가 가장 큰 항목입니다.**

### 7.5 시간별 스냅샷 크론 (P0)

판다랭크의 시간대 칩(6개 = 최소 6시간 롤링)을 재현하려면 **일 1회로는 불가**합니다.

| 항목 | 이전 설계 | v2 수정안 | 사유 |
|---|---|---|---|
| 주기 | 일 1회 06:00 KST | **매시 정각** (08~22시 KST) | 시간대 칩 UX 요구사항 |
| 대상 | 추적 키워드 전체 | 상위 500개 + 사용자 추적분 | API 쿼터 보호 |
| 보관 | 무기한 | 시간 단위 7일 / 일 단위 무기한 | 스토리지 비용 |

Vercel Hobby는 크론 실행 빈도 제한이 있으므로(**확인 필요** — 플랜 정책 변동), 시간당 실행은 GitHub Actions 스케줄러로 빼는 편이 안전합니다.

### 7.6 리스크

1. **법적 리스크(최상)** — 판다랭크는 게시글 진단 하단에 "데이터진단 (독)차권을 출원한 판다랭크의 지적재산으로, 무단 도용 시 민형사상 처벌" 을 명시했습니다. UI 레이아웃·문구·지표 명칭의 직접 모방은 피하고, 지표 정의를 **독자 산식으로 재설계**하십시오. 특허 출원 범위 **확인 필요**(KIPRIS 검색 권장).
2. **네이버 약관** — SERP 크롤링은 위반 소지. 기본은 Open API, 크롤링 경로는 `ENABLE_SERP_CRAWL=false` 기본값으로 격리.
3. **API 쿼터** — 네이버 검색 API 일 25,000회. 시간당 500키워드 × 15시간 = 7,500회로 여유는 있으나 사용자 온디맨드 호출과 합산 관리 필요.
4. **LLM 비용** — 페르소나 분석은 글 30개 입력 = 회당 토큰 부담이 큼. 결과를 반드시 캐싱하고 `[다시 분석하기]`는 주 1회로 제한(판다랭크와 동일).
