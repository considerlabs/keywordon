# 1. 핵심 결론

## 1.1 목표 서비스 정의

KeywordOn을 단순 키워드 조회 서비스에서 아래의 역할을 수행하는 **개인용 콘텐츠 운영 시스템(Content Operating System)** 으로 확장한다.

```text
키워드 탐색
   ↓
콘텐츠 기회 평가
   ↓
콘텐츠 주제 선정
   ↓
AI 기반 초안·이미지·숏폼 대본 생성
   ↓
발행 전 품질 진단
   ↓
수동 발행
   ↓
발행 후 성과 기록 및 개선 추천
   ↓
다음 콘텐츠 기획으로 환류
Copy
가칭 서비스명은 기존 서비스명을 유지하여 다음과 같이 정의한다.

KeywordOn Studio
키워드 데이터와 개인 콘텐츠 자산을 연결하는 개인용 콘텐츠 인텔리전스 시스템

1.2 PandaRank에서 벤치마킹할 핵심 구조
PandaRank의 강점은 개별 기능이 아니라 아래의 연결된 콘텐츠 성장 루프다.

단계	PandaRank 관찰 기능	KeywordOn Studio 적용 방향
1. 주제 발굴	키워드 분석, 황금 키워드, 실시간 트렌드	기존 KeywordOn 기능을 고도화
2. 채널 이해	블로그 분석, 등급, 카테고리, 스타일 분석	개인 블로그 포트폴리오·콘텐츠 자산 분석
3. 콘텐츠 생산	블로그 글쓰기, 제목 생성, AI 이미지, SNS 제작	AI Studio로 통합
4. 품질 검수	게시글 진단, 키워드 노출, 이미지 수, 문단 분석	콘텐츠 품질 점검기 구현
5. 콘텐츠 확장	AI 숏폼, 블로그 URL 기반 영상화	블로그 글 → 숏폼 대본·장면 구성 전환
6. 성과 회고	블로그 순위, 최근 진단, 리포트	개인 성과 기록과 콘텐츠 개선 제안
7. 운영 자동화	오늘의 할 일, 트렌드 추천, 콘텐츠 작업 연결	일일 콘텐츠 브리핑 및 작업 큐

개인용 무료 서비스의 목적과 맞지 않으므로 아래 기능은 개발 범위에서 제외한다.

2.1 현재 공개 화면에서 확인된 메뉴 구조
KeywordOn 공개 화면 기준으로 현재 다음 기능이 확인된다.

메뉴	URL 예시	현재 역할	평가

대량 키워드 조회	/bulk	최대 50개 키워드 비교	유지·고도화

플랜 보기	/shop	유료 플랜 안내	개인용 전환 시 제거 또는 숨김
현재 KeywordOn의 강점
키워드 중심의 진입 구조가 명확하다.
네이버·구글 키워드 분석이라는 핵심 가치가 이미 잡혀 있다.
검색량, 검색 추이, CPC, 경쟁도, 연관어, 기회지수라는 데이터 구조가 존재한다.
/bulk, /discover, /copilot이 이미 콘텐츠 제작 전 단계와 연결될 수 있는 메뉴 구조다.
분석 URL이 쿼리 파라미터 기반이므로 공유·저장·재조회 구조로 확장하기 좋다.

키워드 발굴	시드 확장 중심	검색 의도·콘텐츠 유형·내 블로그 적합도까지 평가

수익화/플랜	유료 서비스 전제	개인용에서는 삭제하고 “내 사용량/작업 현황”으로 대체
성과 측정	키워드 데이터 위주	발행 콘텐츠의 상태·성과·개선 이력 관리 추가 필요

6. 핵심 사용자 시나리오
6.1 시나리오 A: 키워드에서 블로그 콘텐츠까지
Copy1. 사용자가 “보험영업 성과관리”를 검색한다.
2. KeywordOn이 검색량, 추이, 연관 키워드, 경쟁도, 기회점수를 표시한다.
3. 사용자는 “보험영업 성과관리 KPI”를 저장한다.
4. 시스템은 기존 발행 콘텐츠와 중복 여부를 검사한다.
5. 사용자는 “콘텐츠 브리프 생성”을 선택한다.
6. AI가 독자, 검색 의도, 경쟁 콘텐츠 차별점, 목차를 제시한다.
7. 사용자가 승인한 목차로 초안을 생성한다.
8. 발행 전 진단이 구조·출처·키워드·CTA를 점검한다.
9. 사용자가 네이버 블로그에 수동 발행한다.
10. 발행 URL과 성과 데이터를 KeywordOn에 기록한다.
11. 시스템이 30일 후 “업데이트 필요 여부”를 다시 제안한다.
6.2 시나리오 B: 기존 블로그 글을 숏폼으로 전환
Copy1. 사용자가 기존 블로그 URL을 입력한다.
2. 시스템이 제목, 본문, 핵심 주장, 수치, CTA를 추출한다.
3. 사용자가 30초 YouTube Shorts를 선택한다.
4. AI가 3초 훅, 5개 장면, 자막, 내레이션을 생성한다.
5. 사용자가 장면별 문구를 수정한다.
6. 시스템이 CapCut용 대본 Markdown 또는 CSV를 내보낸다.
7. 사용자가 영상 편집 도구에서 최종 영상을 제작한다.
8. 발행 후 조회수·저장·댓글을 수동 기록한다.
6.3 시나리오 C: 오래된 콘텐츠 업데이트
Copy1. 홈 화면에 “90일 이상 업데이트되지 않은 핵심 글”이 표시된다.
2. 사용자가 콘텐츠를 선택한다.
3. 시스템이 오래된 수치, 깨진 링크, 최신성 부족 문장을 표시한다.
4. 현재 키워드 추이와 새 연관어를 다시 분석한다.
5. AI가 업데이트 제안 초안을 생성한다.
6. 사용자가 수정 후 발행일과 업데이트 이력을 저장한다.

AI는 콘텐츠를 “대신 발행하는 도구”가 아니라 리서치·구조화·초안 작성·검수 보조 도구로 사용한다.

필수 규칙
Copy1. 근거 없는 수치 생성 금지
2. 날짜·통계·시장 수치에는 출처 필요
3. 원문 자료가 없는 경험담을 사실처럼 생성하지 않음
4. AI 생성 결과는 “초안”임을 UI에서 명시
5. 발행 전 진단을 통과하지 않아도 발행은 가능하되 경고를 표시
6. 사용자의 문체 프로필과 브랜드 가이드를 우선 적용
7. 기존 콘텐츠와 의미상 중복 가능성을 검사

15.3 성과 KPI
성과는 채널별 공식 데이터 연동 여부에 따라 정확도가 달라진다.

KPI	우선순위	데이터 출처
조회수	높음	채널 통계 또는 수동 입력
검색 유입	높음	검색 콘솔 또는 수동 입력
평균 체류시간	중간	분석 도구 연동 필요

상담·문의 전환	높음	CRM 또는 수동 입력
숏폼 조회·저장·댓글	중간	플랫폼 통계 또는 수동 입력
조회수와 매출의 관계는 콘텐츠 유형·채널·상품 구조에 따라 달라진다.

## 실행 권고사항

1. **가장 먼저 할 일은 `/shop` 중심의 유료 구조를 걷어내고**, `저장 키워드 → 콘텐츠 프로젝트 → AI 브리프` 흐름을 만드는 것입니다.  
2. 첫 MVP에서는 블로그 분석을 복잡한 외부 “순위”로 만들지 말고, **내 글 DB를 축적하고 콘텐츠 품질·주제 커버리지를 분석**하는 방향으로 시작하는 것이 안전합니다.  
3. 개발 순서는 아래가 가장 효율적입니다.

```text
키워드 저장
→ 콘텐츠 프로젝트
→ AI 브리프/초안
→ 콘텐츠 진단
→ 캘린더
→ 기존 블로그 자산 분석
→ 숏폼 전환
→ 자동 리포트
